# 三级能力体系 · 判定、目录与表达

本文件回答三个问题：**这项能力属于哪一层**、**它能迁到哪些行业**、**它该怎么在简历和面试里被表达**。

它不回答「怎么练」——那是 `track-dimensions.md` 的职责。两文件分工见第六节，请勿越界写作。

---

## 一、三级判定

### 1.1 三层不是「由浅到深」

常见的误读是把 L1/L2/L3 当成能力水平的高低。实际上它们描述的是**行业绑定度**，与水平无关：

| 层 | 名称 | 一句话定义 | 验收方 |
| --- | --- | --- | --- |
| **L1** | 垂类专属 | 换行业后必须重新学习该行业的语境、规范、术语才能使用的能力 | 行业内部（监管、同行、客户行业标准） |
| **L2** | 非垂类通用 | 有可交付物、可被任意行业按同一口径验收的能力 | 通用管理口径（交付、指标、协作） |
| **L3** | 跨类迁移 | 作用于「能力本身」的元能力：评估、拆解、改写、规划 | 用户自己的决策质量 |

一个做了十年的资深文案，其内容生产能力仍是 L1——深度不改变层级，只改变 L1 的熟练度。
一个刚毕业但能独立拆解陌生 JD 的学生，其岗位拆解能力已是 L3。

### 1.2 判定树（按序问，前一问命中即停）

1. 换一个行业后，这项能力是否需要重新学习行业语境才能用？
   **是 → L1**
2. 这项能力是否有可交付物（系统／报告／活动／文档／方案），且能被跨行业按同一口径验收？
   **是 → L2**
3. 这项能力是否用于「评估能力、拆解岗位、改写经历、规划路径」本身？
   **是 → L3**
4. 三问皆否 → 它不是能力项，是工具操作或证书。归入对应能力的 `evidence` 字段，不单列。

### 1.3 唯一裁决口径：证据的验收方

当一项能力同时像 L1 又像 L2 时，**只看证据由谁验收**，不看措辞：

- 验收方是**行业内部**（监管机构、同行评审、客户行业标准、平台规则）→ L1
- 验收方是**通用管理口径**（按期交付、成本、协作效率、文档可用性）→ L2

### 1.4 易混淆情形判定表

| 情形 | 判定 | 依据 |
| --- | --- | --- |
| 「会 SQL」 vs 「能定义指标口径与数仓模型」 | 前者 L2（`L2-DATA-LITERACY` 的证据），后者 L1（`L1-DATA-MODEL`） | 是否涉及行业口径决策 |
| 「写周报」 vs 「对外传播内容，有阅读量与转载」 | 前者 L2（`L2-WRITTEN-EXPR`），后者 L1（`L1-CONTENT-PROD`） | 验收方是内部流程还是外部受众 |
| 「在 3 个行业都做过跨部门协调」 | 仍是 L2，**不因跨行业升 L1** | L1 要求行业规范深度，不是经历广度 |
| 「带过 5 人团队」 vs 「建立的方法论被外部采用」 | 前者 L2（`L2-PROJECT-DELIVERY`），后者 L1 | 影响力是否越出组织边界 |
| 「做过行业研究」 vs 「研究结论被投资决策采纳」 | 前者可 L2（`L2-STRUCT-PROBLEM`），后者 L1（`L1-COMMERCIAL-ANALYSIS`） | 是否进入行业决策链 |
| 「熟练使用 Figma」 | 不是能力项 | 工具操作，写入对应能力的 `evidence` |
| 「沟通能力强」但无任何证据 | 记 L2、`lv=1`、`evidence="[待补充]"` | 无证据不得高于 1 级 |

### 1.5 自评的硬约束

- 每层至少 1 项，总数 5–16 项。三层全空的用户，先做能力盘点而不是投简历。
- `lv` 只能取 0–4，且必须能说出依据。说不出依据的一律记 1。
- 标 `soft: true` 的项（软能力），证据必须走第四节的句式库改写，不允许保留「沟通能力强」这类原话。

## 二、能力目录

九个能力族（`cat`，用于跨层迁移匹配）：`tech data content research business compliance process people meta`。

> `cat` 与层级是两条独立的轴。同一族里可能同时有 L1 与 L2 项（如 `data` 族下的 `L1-DATA-MODEL` 与 `L2-DATA-LITERACY`）——这正是「同一能力的不同深度可以分别定价」的体现。
> L3 独占 `meta` 族：元能力没有相邻能力可以替代，因此 L3 缺口永远需要真实补齐，不接受迁移折价。

### 2.2 L1 垂类专属

#### `L1-TECH-BUILD` 技术方案落地与系统交付

- **能力定义**：把模糊需求转为可运行系统，并对延迟、吞吐、可用性、成本等工程指标负责。含技术选型、架构权衡、实现、上线、度量与回滚。
- **核心可迁移点**：需求→约束识别→方案权衡→最小可行实现→指标验证的闭环；不确定性下的取舍框架；对技术债与交付节奏的权衡意识。迁移时折价发生在**行业约束**（合规、设备、遗留系统），不在**工程方法**本身。
- **垂类岗位适配场景**：
  - 互联网／软件：推荐系统在线服务，在 QPS 与 P99 延迟约束下改造召回链路
  - 智能制造：产线设备数据采集网关，需在弱网、离线、老旧 PLC 协议下保证不丢数
  - 金融科技：交易对账批处理，需满足幂等、可回溯与审计留痕
  - 医疗信息化：院内系统对接，需满足数据分级与脱敏要求
- **非垂类岗位适配场景**：企业信息化（内部工具与自动化）、技术售前（方案可行性评估）、技术项目管理（排期与风险判断）、开发者关系（技术内容与布道）。
- **跨行业应用案例**：某消费电子企业要把质检从人工抽检改为视觉抽检。先定义「漏检率／误检率／单件耗时」三个验收指标，两周做出最小闭环，用产线真实图片迭代。结果：漏检率由 `[待补充]%` 降至 `[待补充]%`，单件耗时下降 `[待补充]%`，方案被复制到 `[N]` 条产线。

#### `L1-DATA-MODEL` 数据建模与指标口径设计

- **能力定义**：定义业务指标的计算口径、维度模型与可复现的数据链路，使不同人算出同一个数。
- **核心可迁移点**：口径先行的思维方式；维度建模（事实表／维表／粒度）的通用范式；对「同名词不同义」的敏感度；数据血缘与可复现性要求。跨行业折价发生在业务语义（什么算「活跃」因行业而异），不在建模方法。
- **垂类岗位适配场景**：
  - 电商：GMV 口径（是否含退款、是否含运费）与商品维度模型
  - 金融：风险敞口口径与客户统一视图
  - 物流：时效达成率口径（起算点、承诺口径、异常剔除规则）
  - 教育：完课率与续费率的定义对齐
- **非垂类岗位适配场景**：经营分析（管理驾驶舱口径统一）、财务 BP（管理口径与核算口径桥接）、产品运营（埋点方案设计）、数据治理（指标字典维护）。
- **跨行业应用案例**：某连锁零售的「门店坪效」在三个部门有三个算法，月度会议反复对不上数。动作：牵头梳理 11 个核心指标的口径文档，明确粒度、分子分母、异常剔除规则，落成指标字典并接入 BI。结果：会议对数时间由 `[待补充]` 小时降至 `[待补充]`，指标口径争议归零，字典被 `[N]` 个业务线复用。

#### `L1-CONTENT-PROD` 内容生产与叙事结构

- **能力定义**：从选题、结构、表达到分发的完整内容生产，对阅读、转化、留存等传播结果负责。
- **核心可迁移点**：受众—场景—信息密度的匹配判断；叙事结构（钩子—冲突—证据—行动）的通用骨架；选题的可验证性（先小样本测再放量）；多平台改写的方法。跨行业折价在平台规则与受众语言，不在结构方法。
- **垂类岗位适配场景**：
  - 互联网内容平台：信息流选题与标题工程
  - 消费品牌：种草脚本与详情页文案
  - 出版机构：图书营销文案与作者访谈
  - 政务／公共机构：政策解读与科普转译
  - B2B 科技公司：技术白皮书与客户案例
- **非垂类岗位适配场景**：企业内训材料（把制度写成可读内容）、招聘雇主品牌（JD 与招聘推文）、产品文档（把功能写成用户能懂的话）、公共关系（对外口径撰写）。
- **跨行业应用案例**：某工业设备厂商的技术优势长期讲不清，销售靠口头解释。动作：把 40 页参数手册重构为「三个典型工况 + 一张对比表 + 五个客户证言」的选型指南，并在行业展会分发。结果：询盘转化率由 `[待补充]%` 升至 `[待补充]%`，销售首次接触的解释时长缩短 `[待补充]%`。

#### `L1-RESEARCH-DESIGN` 研究设计与证据链构建

- **能力定义**：用抽样、访谈、问卷、实验等方法产出可被质疑与复现的结论，并对结论的适用边界负责。
- **核心可迁移点**：从「观点」到「可验证假设」的转化；样本代表性与偏差识别；证据链（主张—证据—反证—边界）的搭建；定性材料的编码与三角验证。跨行业折价在领域先验（什么算异常、什么算常识），不在方法。
- **垂类岗位适配场景**：
  - 互联网：用户研究与可用性测试
  - 咨询：行业研究与专家访谈
  - 医疗／公共卫生：临床观察与流行病学调查
  - 教育：教学效果评估与学情分析
  - 政府／智库：政策评估与社会调查
- **非垂类岗位适配场景**：市场调研（竞品与用户画像）、人力资源（组织诊断与离职归因）、产品质量（客诉归因分析）、投资尽调（业务真实性核验）。
- **跨行业应用案例**：某教育机构续费率下滑，内部归因为「老师水平」。动作：设计三组对照——在读学员问卷（N=`[待补充]`）、流失学员深访（N=`[待补充]`）、同期课程完成度数据比对。结果：真实主因是排课时段与家长工作时间冲突，而非教学质量；调整排课后次月续费率回升 `[待补充]` 个百分点。

#### `L1-COMMERCIAL-ANALYSIS` 商业分析与估值建模

- **能力定义**：拆解商业问题并建模，输出能支撑决策的量化判断，含市场规模测算、单位经济模型、敏感性分析。
- **核心可迁移点**：把业务问题翻译成可计算结构的能力；自下而上与自上而下两种测算的交叉验证；对假设的显式化与敏感性排序；单位经济（UE）思维。跨行业折价在行业财务特征（毛利结构、周转周期、获客成本量级）。
- **垂类岗位适配场景**：
  - 消费：单店模型与开店测算
  - SaaS／科技：ARR 拆解、CAC/LTV 与留存队列
  - 制造：产能利用率与单位成本分析
  - 医疗：科室盈亏与医保支付影响测算
  - 能源：项目 IRR 与电价敏感性
- **非垂类岗位适配场景**：战略规划（业务组合取舍）、投资分析（标的估值）、采购与供应链（总拥有成本建模）、政府与园区（产业规划测算）。
- **跨行业应用案例**：某连锁餐饮要判断是否进入新城市。动作：搭单店模型（租金、人效、翻台、客单、损耗五个假设），做三档情景与敏感性排序，识别出「翻台率」是第一敏感因子，先做快闪店验证。结果：避免 `[N]` 家门店的错误投入，快闪店实测翻台 `[待补充]`，据此修正模型后首批开店 `[N]` 家。

#### `L1-COMPLIANCE` 合规与风险审查

- **能力定义**：按特定法域与监管口径识别、分级、留痕风险，并给出可执行的整改路径。
- **核心可迁移点**：规则检索与适用性判断；风险分级（可能性 × 影响）的通用框架；留痕与可审计意识；把监管语言翻译成业务动作的能力。跨行业折价在具体法域与监管口径，不在方法论。
- **垂类岗位适配场景**：
  - 金融：反洗钱、适当性管理、信息披露
  - 医疗：数据合规、临床试验伦理审查
  - 互联网：个人信息保护、内容审核规则
  - 制造：安全生产、环保排放、出口管制
  - 跨境贸易：关税与原产地规则
- **非垂类岗位适配场景**：内控与审计（流程风险点梳理）、采购合规（供应商准入审查）、人力资源（劳动用工合规）、数据治理（分级分类与授权）。
- **跨行业应用案例**：某跨境业务要上线新市场，法务排期两个月。动作：先按「数据跨境／支付牌照／广告用语／消费者权益」四类做风险清单，标注每条的法律依据与责任部门，把可并行项前置。结果：上线周期由 `[待补充]` 周压缩至 `[待补充]` 周，上线后零监管问询，清单被复用到 `[N]` 个市场。

### 2.3 L2 非垂类通用

#### `L2-STRUCT-PROBLEM` 结构化问题拆解

- **能力定义**：把模糊问题拆成可验证的假设与可执行的动作，并对拆解的完备性负责。
- **核心可迁移点**：MECE 式的拆解纪律；假设驱动（先立可被推翻的判断，再找证据）；问题—原因—方案三层的分离；优先级排序（影响 × 可控性）。
- **垂类岗位适配场景**（含该能力在此岗位的硬贡献指标）：
  - 制造业生产管理：把「交期延误」拆成产能、物料、排程、质量四支，按期交付率
  - 医院医务管理：把「门诊等待时间长」拆成号源、检查、缴费、取药四段，平均候诊时长
  - 券商投行：把「发行失败风险」拆成定价、路演、合规三支，发行认购倍数
  - 政务窗口：把「办事跑多次」拆成材料、告知、系统三支，一次办结率
- **非垂类岗位适配场景**：咨询顾问（项目主问题拆解）、产品经理（需求归因）、运营（指标异常归因）、审计（风险点分解）。
- **跨行业应用案例**：某物流公司「投诉率高」，各部门互相推诿。动作：把投诉按环节（下单、揽收、中转、派送、售后）与原因（时效、破损、态度、信息不准）做二维归集，识别 62% 集中在中转信息不更新。结果：投诉率下降 `[待补充]%`，责任归属从「集体」变为「可定位到环节」。

#### `L2-DATA-LITERACY` 数据素养与指标解读

- **能力定义**：读得懂数据、算得对指标、说得清结论的边界，不被相关性误导。
- **核心可迁移点**：分母意识（谁在被平均）；对比基准的选择；相关与因果的区分；幸存者偏差与选择偏差的识别；用一张图说清一件事的能力。
- **垂类岗位适配场景**：
  - 零售：门店同店增长 vs 新店贡献的拆解，同店增长率
  - 教育：续费率按班型／时段分层，分层续费率差异
  - 医疗：科室周转与平均住院日的关系，床位周转次数
  - 制造：良率波动的批次归因，批次良率标准差
- **非垂类岗位适配场景**：市场投放（渠道 ROI 与归因）、人力资源（人效与编制测算）、供应链（库存周转与缺货率）、公共管理（统计口径解读）。
- **跨行业应用案例**：某 SaaS 公司「客户数增长 30%」被写进月报。动作：拆解为新签、流失、扩容三部分，发现新签 +45% 但流失率从 8% 升到 15%，净增仅 12%。结果：月报口径改为「净留存」，并推动流失归因项目，季度流失率回落至 `[待补充]%`。

#### `L2-PROJECT-DELIVERY` 项目推进与交付管理

- **能力定义**：在范围、时间、资源约束下把事推到交付，并对交付质量与节奏负责。
- **核心可迁移点**：范围—时间—资源的三角权衡；关键路径识别；风险前置与预案；里程碑与验收标准的设定；跨角色排期的协调机制。
- **垂类岗位适配场景**：
  - 建筑／工程：工期与工序穿插，按期竣工率
  - 会展／活动：多供应商协同，活动零事故率
  - 软件研发：版本节奏与发布质量，发布回滚率
  - 医院基建：科室搬迁与设备进场，停诊时长
- **非垂类岗位适配场景**：PMO（多项目组合管理）、市场活动（campaign 落地）、政府项目（专项推进）、创业公司（从 0 到 1 交付）。
- **跨行业应用案例**：某医院新院区搬迁，涉及 23 个科室、4 家设备商。动作：按「停机窗口」倒排关键路径，把设备调试与科室培训并行，设三个决策检查点。结果：停诊时长控制在 `[待补充]` 小时（原计划 `[待补充]`），零设备事故，方案被同集团另两家医院复用。

#### `L2-STAKEHOLDER` 跨部门沟通与干系人管理

- **能力定义**：识别利益相关方、对齐预期、收敛分歧，让决策在正确的层级发生。
- **核心可迁移点**：干系人地图（影响力 × 关切度）；把「立场分歧」还原为「利益分歧」；向上沟通的结论先行；会议设计与决议留痕；对「不表态」的识别。
- **垂类岗位适配场景**：
  - 制造业供应链：采购、生产、销售的三角协调，物料齐套率
  - 医院医务科：临床、护理、行政的流程对齐，跨科协作投诉数
  - 券商投行：企业方、律所、会所、监管的多方对齐，反馈闭环周期
  - 政府项目：多部门联合发文，会签周期
- **非垂类岗位适配场景**：HRBP（业务与人力政策对齐）、客户成功（客户内部推动）、公共事务（政府关系）、创业公司（投资人沟通）。
- **跨行业应用案例**：某集团推行统一采购，三个事业部抵制。动作：先做干系人地图，识别真正阻力是「事业部担心响应速度」，于是把「紧急采购绿色通道」写进制度并给出 SLA。结果：制度落地率 `[待补充]%`，采购成本下降 `[待补充]%`，无一起因响应慢导致的停线。

#### `L2-WRITTEN-EXPR` 书面表达与文档工程

- **能力定义**：产出结构清晰、可被他人直接使用的文档，让信息不依赖口头传递。
- **核心可迁移点**：结论先行的结构；读者分层（决策者看结论、执行者看步骤）；模板化与可复用；把隐性知识显性化；版本与变更记录意识。
- **垂类岗位适配场景**：
  - 制造：作业指导书与工艺文件，新员工上手周期
  - 医疗：临床路径与护理记录，记录返修率
  - 金融：尽调报告与投研纪要，报告一次通过率
  - 政府：政策文件与办事指南，群众咨询量
- **非垂类岗位适配场景**：技术写作（API 文档）、法务（合同与制度）、咨询（交付报告）、运营（SOP 与知识库）。
- **跨行业应用案例**：某制造企业老师傅退休导致工艺断档。动作：把 12 道关键工序的「手感判断」转成可测量的参数区间与判定图例，形成图文作业指导书。结果：新员工独立上岗周期由 `[待补充]` 周缩短至 `[待补充]` 周，工序不良率下降 `[待补充]%`。

#### `L2-LEARNING` 快速学习与技术迁移

- **能力定义**：在有限时间内掌握陌生领域的够用知识并投入使用，且知道自己的知识边界在哪。
- **核心可迁移点**：先建地图再补细节；用最小可运行样本验证理解；找到该领域的权威信源；把新知识挂到已有知识结构上；主动标注「不确定区」。
- **垂类岗位适配场景**：
  - 互联网：两周上手陌生技术栈并交付需求，首次交付返工率
  - 制造：接手新产线工艺，试产合格率
  - 医疗：轮转新科室的病种学习曲线，独立处置占比
  - 金融：切换新行业研究覆盖，首份报告获采纳率
- **非垂类岗位适配场景**：咨询（快速进入陌生行业）、销售（新产品线学习）、创业（跨领域补课）、内部转岗（新职能上手）。
- **跨行业应用案例**：某分析师从消费切换到新能源研究。动作：先用两周搭「产业链—玩家—价格机制—政策」四层地图，再挑 3 家代表公司做深度拆解反推行业逻辑，输出一份内部扫盲报告。结果：首份正式报告获客户采纳，覆盖标的数由 0 到 `[N]`，被团队用作新人上手材料。

### 2.4 L3 跨类迁移

L3 是元能力，它的产出物是**决策质量的提升**，而非某个业务交付物。四项构成一条完整链路：先看清自己（自评）→ 再看清岗位（拆解）→ 再改造表达（改写）→ 最后规划路线（路径）。

#### `L3-CAP-MATRIX` 能力矩阵自评

- **能力定义**：说清自己每项能力的层级、熟练度与证据，并能对缺口排序。
- **核心可迁移点**：把「我觉得我会」转成「有什么证据、由谁验收」；诚实标注 `[待补充]`；区分「做过」与「能独立负责」。
- **判定「已具备」的证据**：能对 16 项中的每一项说出 `lv` 的依据；缺口能按「影响 × 补齐成本」排序，而不是列一张平铺的待办清单。
- **垂类／非垂类场景**：任何求职场景的第一动作。垂类求职用它确认「我够不够深」；跨行业求职用它确认「我有什么能带走」。
- **跨行业应用案例**：某考生自评「数据分析能力强」，矩阵化后发现 L1 的 `L1-DATA-MODEL` 只有 lv1（只会跑现成报表），但 L2 的 `L2-DATA-LITERACY` 达 lv3（能拆口径、能识别归因偏差）。据此把求职方向从「数据分析师」调整为「业务分析／经营分析」，投递命中率显著提升。

#### `L3-JOB-DECONSTRUCT` 岗位能力拆解

- **能力定义**：把一份 JD 拆成带层级与权重的能力要求清单，识别哪些是门槛、哪些是加分、哪些是套话。
- **核心可迁移点**：从「要求描述」还原「实际工作」；识别隐性要求（汇报对象、协作密度、交付节奏）；给要求定级（L1/L2/L3）与定权（必须／优先／加分）。
- **判定「已具备」的证据**：能把一份真实 JD 拆成 ≥6 条能力要求，每条给出层级与权重，且能指出至少 1 条「JD 没写但实际必需」的能力。
- **垂类／非垂类场景**：垂类求职用它精修简历关键词；跨行业求职用它判断「这个岗位要的到底是行业经验还是通用能力」——这是决定能否转型的关键判断。
- **跨行业应用案例**：某传统媒体编辑想投互联网运营。拆解 10 份 JD 后发现：真正被反复要求的是「选题判断 + 数据复盘 + 跨部门推进」，而非「互联网从业经验」。据此重写简历，把纸媒的选题会与发行数据复盘改写成对应语言，拿到 `[N]` 个面试。

#### `L3-EXP-REWRITE` 经历迁移改写

- **能力定义**：同一段经历，按不同行业的话语体系重写，事实不变、视角切换。
- **核心可迁移点**：识别经历中的「可迁移内核」（解决了什么问题、用什么方法、产生了什么变化）；把行业术语替换为目标行业的等价概念；保留可核验的事实锚点（数字、角色、时间）。
- **判定「已具备」的证据**：同一段经历能写出面向两个不同行业的版本，且两个版本的事实完全一致、仅术语与侧重不同。
- **垂类／非垂类场景**：垂类求职用它对齐目标公司的内部话语；跨行业求职用它把「不被看懂的深度」翻译成「被认可的广度」。
- **跨行业应用案例**：某医院护士长转投医疗科技公司做客户成功。原表述「负责病区护理质量管理」；改写为「面向 40 张床位的终端用户，负责使用流程落地与问题闭环，把新流程依从率从 `[待补充]%` 提升到 `[待补充]%`」。事实未变，但目标岗位能读懂其价值。

#### `L3-PATH-PLAN` 跨行业路径规划

- **能力定义**：基于现有能力设计弯路最少的迁移路线，明确跳板能力、折价补偿动作与时间节点。
- **核心可迁移点**：识别「跳板岗位」（能同时用到旧能力与新方向的最小切换点）；估算迁移折价（降级幅度、薪资让步、时间成本）；设计补偿动作（证书、作品、内推、兼职项目）。
- **判定「已具备」的证据**：能给出 12／24 周两档路线，每条路线含「跳板岗位—需补能力—验证方式」，并说明为什么这条路比直跳更省。
- **垂类／非垂类场景**：垂类深耕用它规划「从执行到主导」的升级路径；跨行业转型用它规划「先跳到哪、再跳到哪」。
- **跨行业应用案例**：某制造业工艺工程师想转产品经理。直投产品岗零回应；规划为「制造业 SaaS 的实施顾问（6 个月）→ 产品经理（12 个月）」两跳，第一跳复用工艺背景，第二跳复用客户场景理解。结果：第一跳 2 个月内拿到 offer，第二跳在原公司内部转岗完成。

## 三、L2 分级标准

### 3.1 五级行为锚点（通用）

| lv | 名称 | 行为描述 | 可验证证据 |
| --- | --- | --- | --- |
| 0 | 无 | 未接触过 | — |
| 1 | 了解 | 知道概念与方法名，能在他人指导下参与 | 培训记录、课程作业 |
| 2 | 可独立执行 | 能在明确目标下独立完成，不需要逐步指导 | 独立交付的产物、他人评价 |
| 3 | 可主导并优化 | 能主导一件事并改进方法，能带 1–2 人 | 主导的项目、方法改进带来的指标变化 |
| 4 | 可定义标准并带人 | 能定义该能力的标准与流程，能培养他人，影响力越出本团队 | 被外部采用的标准／SOP、培养出的人 |

**关键判据**：lv 的分界线在「是否需要他人给出方法」。需要 → ≤2；能自己改进方法 → ≥3；能定义方法让别人用 → 4。

### 3.2 三个代表项的逐级锚点

**`L2-STRUCT-PROBLEM`**

| lv | 表现 |
| --- | --- |
| 2 | 拿到已拆好的问题清单能逐项推进 |
| 3 | 能独立把模糊问题拆成 MECE 结构，并排出优先级 |
| 4 | 拆解框架成为团队通用方法，被其他团队借用 |

**`L2-PROJECT-DELIVERY`**

| lv | 表现 |
| --- | --- |
| 2 | 能在既定计划下推进自己的任务，按时交付 |
| 3 | 能独立排期、识别关键路径、处理变更与风险 |
| 4 | 能同时管多项目组合，建立团队级交付机制 |

**`L2-STAKEHOLDER`**

| lv | 表现 |
| --- | --- |
| 2 | 能清楚表达自己的诉求，配合他人推进 |
| 3 | 能识别关键干系人并主动对齐，把分歧收敛成决议 |
| 4 | 能在多方利益冲突中促成共识，成为跨部门默认协调人 |

其余三项（`L2-DATA-LITERACY` / `L2-WRITTEN-EXPR` / `L2-LEARNING`）套用 3.1 的通用锚点。

### 3.3 职级映射（L2 最低要求）

| 岗位类别 | L2 最低要求 |
| --- | --- |
| 实习 | 任 2 项 ≥ 2 |
| 校招初级 | 任 3 项 ≥ 2，且至少 1 项达 3 |
| 社招中级（3–5 年） | 4 项 ≥ 3，且至少 1 项达 4 |
| 高级／负责人 | 2 项达 4，其余 ≥ 3 |

低于该岗位类别的最低要求时，简历上的 L2 表述会被视为「自我评价」而非「能力举证」——此时应优先补 L2，而不是继续加深 L1。这是「高性价比原则」的直接推论：L1 每加深一级的边际收益，只在 L2 达标之后才显现。

## 四、「软能力 → 岗位硬贡献」句式库

软能力的失败表达是形容词（「沟通能力强」），成功表达是**可核验的因果链**。

### 4.1 主句式（六槽）

```
在【场景 / 规模】中，用【方法】把【软能力】落到【可交付物】，使【指标】从【A】到【B】。
```

六个槽位缺一不可。缺「规模」则不可信，缺「指标」则无法验收。

### 4.2 六条变体

| 类型 | 句式 | 示例（跨行业） |
| --- | --- | --- |
| 效率 | 把【重复动作】沉淀为【模板／工具】，使【耗时】由【A】降至【B】 | 把周报汇总沉淀为自动取数模板，部门月度汇报准备时间由 6 小时降至 40 分钟 |
| 质量 | 在【场景】中建立【检查机制】，使【缺陷指标】由【A】降至【B】 | 在产科护理交接中建立双人核对清单，交接遗漏由月均 5 起降至 0 |
| 协同 | 主导【N】次【多方评审】，把【X】项分歧收敛为【Y】项决议，决策周期由【A】压缩至【B】 | 主导 9 次跨部门评审，把 14 项口径分歧收敛为 3 项决议，月度对数周期由 5 天压缩至 1 天 |
| 风险 | 在【项目】中前置识别【N】类风险并设预案，使【事故指标】为【结果】 | 在搬迁项目中前置识别 7 类停机风险并设预案，实际停诊 0 小时 |
| 增长 | 通过【动作】把【指标】由【A】提升至【B】，覆盖【规模】 | 通过选题重构与分发时段调整，账号月阅读量由 8 万提升至 31 万，覆盖 12 万粉丝 |
| 复用 | 把【项目】中的【方法】沉淀为【SOP／模板】，被【N】个团队复用，重复工作量下降【X%】 | 把选型评估方法沉淀为打分表，被 4 个事业部复用，方案评审返工下降 35% |

### 4.3 禁用词替换表

| 禁用表达 | 必须替换为 | 替换后必须出现的量化位 |
| --- | --- | --- |
| 沟通能力强 | 主导 N 次多方对齐，把 X 项分歧收敛为 Y 项决议 | 次数、分歧数、决议数、周期 |
| 学习能力强 | 在 N 周内掌握【技能】并交付【产物】，返工 N 次 | 周期、产物、返工次数 |
| 责任心强 | 负责【范围】，连续 N 个周期【指标】达成率 X% | 范围、周期、达成率 |
| 抗压能力强 | 在【约束】下同时推进 N 项，全部按期交付 | 约束、并行数、按期率 |
| 有团队精神 | 承担【超出职责的协作动作】，使【协作指标】改善 | 动作、协作指标 |
| 执行力强 | 把【目标】拆为 N 个里程碑，按期完成 X/N | 里程碑数、按期数 |
| 逻辑思维好 | 用【框架】拆解【问题】，定位到【根因】，使【指标】改善 | 框架、根因数、指标 |
| 有热情／有想法 | 主动发起【项目】，落地为【产物】，带来【结果】 | 项目、产物、结果 |

## 五、三类择业场景

由 `capability_matrix.py` 依阈值判定，阈值见该脚本模块常量。此处只解释语义：

| 代号 | 场景 | 特征 | 策略 |
| --- | --- | --- | --- |
| A | 垂类精准求职 | L1 命中率高，L2 达标 | 加深 L1、用 L1 差异化；简历主打深度 |
| B | 非垂类宽泛择业 | L1 命中一般但 L2 强、迁移率高 | 扩大岗位范围到相邻职能；简历主打可迁移性 |
| C | 跨行业转型 | L1 命中低但 L2 强、迁移率高 | 走跳板岗位；简历主打能力等价物，弱化行业标签 |
| D | 先补地基 | L2 未达标 | 不建议立即投递；先补 L2 至岗位类别最低要求 |

**A 与 B 的边界**不在「想不想转型」，而在「L1 是否够深」。L1 深而强行转 B，是浪费；L1 浅而硬投 A，是碰壁。

## 六、与 `track-dimensions.md` 的分工

两份文件都谈能力，但轴不同，**不要互相抄**：

| | `track-dimensions.md` | 本文件 |
| --- | --- | --- |
| 组织轴 | 学科轨道（sci / art / biz） | 能力层级（L1 / L2 / L3） |
| 回答的问题 | 「我这个专业该补哪些维度」 | 「这项能力属于哪层、能迁到哪、怎么表达」 |
| 视角 | 输入侧（学习路径） | 输出侧（岗位要求与迁移定价） |
| 独有内容 | 每轨道 7 维度、提升动作清单、定位一句话模板 | 判定树、16 项目录、职级分级、软能力句式库 |
| 不写什么 | 不写层级判定与迁移折价 | 不写「怎么练」（指向 `track-dimensions.md` 第四节） |

## 七、引用与版本

- 能力 id 的唯一权威在 `scripts/capability_matrix.py` 的 `CATALOG` 常量；本文件是它的文档化呈现。
- `verify.py` 的 `check_catalog_sync()` 会断言两者 id 集合完全一致，不一致即验收失败。
- 目录版本：`catalogVersion = "1.0"`（与 `profile.capabilityMeta.catalogVersion` 对应）。
- 修改目录时的顺序：先改 `CATALOG` → 再改本文件 → 跑 `verify.py`。
