# v2.0.0 · 三级能力体系 + 能力迁移矩阵

简历工具大多只回答「我差什么」。这一版多回答一个问题：**我已有的能力，能迁到哪。**

## 核心：能力按「谁在验收」分三层，不按熟练度分

| 层 | 名称 | 验收方 | 例子 |
| --- | --- | --- | --- |
| `L1` | 垂类专属 | 行业内的人（技术面试官 / 主编 / 合规负责人） | 技术方案落地、数据建模与指标口径 |
| `L2` | 非垂类通用 | 通用管理标尺（任何行业的 leader 都能判断好坏） | 结构化问题拆解、项目推进、书面表达 |
| `L3` | 跨类迁移 | 求职者自己（元能力，无相邻替代品） | 能力矩阵自评、岗位能力拆解、经历迁移改写 |

判定只问一句话：**这份证据的验收方是谁？**

四条规则，违反任一条结论就是错的：

1. **熟练度高 ≠ 层级高**。十年资深文案的内容能力仍是 `L1`。
2. **`L3` 不打折**。元能力没有相邻替代品，永远不适用迁移折价。
3. **`L2` 必须翻译成硬贡献**。写「沟通能力强」是废话，要走句式库：
   `在【场景/规模】中，用【方法】把【软能力】落到【可交付物】，使【指标】从【A】到【B】。`
4. **跨层同族能力按 0.6 折价**。转型不是从零开始，但也不能按 100% 算。

## 修复

- `render.py` 用 `abs(hash(title))` 做 localStorage key —— `hash()` 受 `PYTHONHASHSEED`
  影响，同一份数据两次渲染会得到不同 key，勾选进度会莫名丢失。改用 `sha1()`。
- `data-contract.md` 漏记 `jobs[].major` / `jobs[].grade`，照文档构造的数据会静默丢掉专业与届别。

## 兼容

## 安装

```bash
git clone https://github.com/NiuBi66666688/job-lailailai.git
cd job-lailailai
python verify.py                 # 先验收
python scripts/install.py --target all --link
```

或下载下方迁移包 zip，解压到任意目录后同样先跑 `python verify.py`。

**零第三方依赖**，不需要执行 `pip install`。

## 升级提示

如果你从 v1.1 升上来，老 `jobs.json` **不需要改**——它会继续按五步渲染。
想用上第 6 步，按 `SKILL.md` 阶段一第 4 轮补一轮能力自评，产出 `profile.json`，
再给每个岗位补 `capabilities`，然后跑：

```bash
python scripts/capability_matrix.py --profile profile.json --jobs jobs.json --merge
```

`matrix` 不要手写——它是脚本的输出，手写会与自评漂移，而页面不会报错。
